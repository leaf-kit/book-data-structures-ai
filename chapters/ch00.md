# 0장 왜 다시 쓰는가

2023년에 공개된 한 추론 서버 논문은 대규모 언어 모델의 메모리 중 60에서 80퍼센트가 낭비되고 있었다고 적었다.

## 절

- **0.1** 자료 구조를 넷의 묶음으로 정의하고, 균일 비용 모델이 깨지는 자리를 잰다
- **0.2** 전통 교과서의 가정 넷을 적고, 루프라인 모델을 세운다
- **0.3** $k$ 최근접 탐색과 재현율을 정의하고, 전수 탐색을 루프라인 위에 놓는다

## 연습문제

- 문제 0.1 (기초) 정의 0.1 의 넷 $(S, Ops, Inv, C)$ 를 큐에 대해 적어라. 불변식을 한 문장으로 쓰고, 균일 비용 모델에서 enqueue 와 dequeue 의 값을 세어라.
- 문제 0.2 (기초) 원소 $n = 10^6$ 개, 원소 크기 8바이트, 라인 64바이트, 캐시 8MB 일 때 정리 0.1 의 두 이동량을 계산하라. 순차와 무작위의 비는 얼마인가.
- 문제 0.3 (기초) 피크 200 GFLOP/s, 대역폭 20 GB/s 인 기계의 능선점을 구하고, 밀도 0.25, 2, 50 인 연산의 달성 가능 처리량을 각각 적어라.
- 문제 0.4 (기초) 예제 0.3 의 점 다섯 개를 단위 벡터로 만든 뒤 $q = (1, 0)$ 에 대해 내적으로 $k = 2$ 를 풀어라. 유클리드 거리로 푼 답과 같은지 확인하라.
- 문제 0.5 (응용) `bench/c00_cost.py` 의 원소 크기를 float64 로 바꿔 다시 재라. 비율이 갈라지는 원소 수가 절반이 되는지 확인하고, 그 이유를 정리 0.1 로 설명하라.
- 문제 0.6 (응용) `dsai.cost.blocks_touched` 로 실험 0.1 의 각 행에서 두 순서가 건드리는 라인 수를 세고, 잰 시간의 비율과 라인 수의 비율을 한 표에 놓아라.
- 문제 0.7 (응용) `dsai.roofline` 에 원소별 곱 (두 벡터의 같은 자리끼리 곱해 새 벡터를 만드는 연산) 의 $$ 와 $$ 함수를 더하고, 밀도를 구해 실험 0.2 의 표에 한 줄 더하라.
- 문제 0.8 (응용) `dsai.knn.knn_bruteforce` 에 질의 여러 개를 한 번에 받는 판을 만들어라. 질의 64개를 한 번에 처리할 때 질의당 지연이 얼마나 줄고 밀도가 얼마가 되는지 재라.
- 문제 0.9 (탐구) 정리 0.1 은 캐시가 라인을 완벽히 골라 남긴다고 가정한다. LRU 교체 정책에서 무작위 순열 접근의 기대 이동량이 이 하한과 얼마나 다른지 논하라. 시뮬레이션으로 재도 좋다.
- 문제 0.10 (탐구) 루프라인은 이동량을 주기억 하나에서만 센다. 캐시 층마다 지붕을 하나씩 그린 다층 루프라인에서 실험 0.2 의 행렬 벡터 곱이 어느 지붕에 붙는지 추정하라.

## 더 읽을 것

- Roofline: An Insightful Visual Performance Model for Multicore Architectures (2009). 루프라인 모델의 원전. 여덟 쪽이고 그림이 전부다. 이 장의 실험 0.2 를 읽고 나서 보면 한 시간에 끝난다. (0.2절)
- The Input/Output Complexity of Sorting and Related Problems (1988). 이동량 모델의 원전. 디스크 시대의 논문이지만 정리의 형식은 그대로 캐시에 옮겨진다. (0.1절)
- Cache-Oblivious Algorithms (1999). 라인 크기를 모르고도 최적인 알고리즘. 15장의 타일링이 이 논문 위에 서 있다. (0.1절)
- A New Golden Age for Computer Architecture (2019). 범용 프로세서의 성능 향상이 왜 멈췄는지. 이 책의 주제가 왜 지금 문제인지를 두 저자가 적었다. (0.2절)
