# 16장 분산과 저장

1964년의 논문은 다섯 줄이었다.

## 절

- **16.1** 링 all-reduce. 기계 하나가 보내는 것이 벡터 두 개 이하이고 그것이 하한. 단계 지연이 조각 200 KB 아래에서 시간
- **16.2** 머클 트리와 내용 주소 저장. 블록 4 KB 가 1 MB 보다 스무 배 적게 저장, 트리는 다른 블록이 드물 때만 로그
- **16.3** 열 지향 저장과 메모리 맵. 열 하나에 바이트 8 배, 시간 3 배에서 6 배
- **16.4** 셔플과 순열. 균등성의 증명, 블록 섞기의 순차, 저장 없는 Feistel 순열

## 연습문제

- 문제 16.1 (기초) 매개변수 70억 개를 2 바이트로 둔 기울기를 기계 8 대가 링으로 합칠 때 기계 하나가 보내는 바이트와 단계 수를 앞의 정의 로 구하라. 별의 뿌리는 얼마인가. 링크가 400 GB/s 이면 각각 몇 밀리초인가.
- 문제 16.2 (기초) 블록 $2^20$ 개의 머클 트리는 층이 몇 개인가. 다른 블록 100 개를 찾는 해시 비교 수를 앞의 정의 로 구하고, 전부 비교가 나아지는 $k$ 의 경계를 적어라.
- 문제 16.3 (기초) 열 여덟 개, 레코드 64 바이트, 행 $10^8$ 개의 표에서 열 하나를 읽을 때 행 저장과 열 저장이 닿는 바이트를 앞의 정의 로 구하라. 10 GB/s 이면 각각 몇 밀리초인가.
- 문제 16.4 (기초) $n = 10^9$ 에서 앞의 정의 의 반쪽 비트 수와 정의역 크기를 구하고, 사이클 걷기의 기대 반복을 적어라. 순열을 저장하면 몇 GB 인가.
- 문제 16.5 (응용) 이진 트리로 모으고 내려보내는 all-reduce 를 구현하라. 단계가 $2 _2 p$ 인지, 기계 하나의 바이트가 링보다 큰지 시험하고, 어느 조건에서 트리가 링을 이기는지 앞의 정의 으로 논하라.
- 문제 16.6 (응용) 구르는 해시로 블록 경계를 정하는 내용 정의 청킹을 구현하라. 한 바이트를 끼워 넣었을 때 고정 블록은 거의 전부를 다시 저장하고 내용 정의 블록은 하나만 다시 저장하는지 `dsai.merkle.ContentStore` 로 시험하라.
- 문제 16.7 (응용) 정렬된 정수 열에 런 길이 부호화를 얹어라. 값과 길이 두 배열로 저장하고, 풀지 않고 합을 구하며, 저장이 원래의 백분의 일 아래인지 시험하라. 행 저장에서는 왜 이 압축이 안 되는가.
- 문제 16.8 (응용) `dsai.loader.block_shuffle` 의 블록 크기를 1 에서 $n$ 까지 바꾸며 같은 블록에 연속으로 머무는 비율과 원소가 원래 자리에서 옮겨 간 거리의 평균을 재라. 어느 쪽이 블록 크기에 달렸고 어느 쪽이 무관한가.
- 문제 16.9 (탐구) 링은 대역폭 최적이지만 단계가 $p$ 에 선형이다. 벡터 크기와 기계 수의 평면에서 링과 트리의 경계를 앞의 정의 으로 그리고, 링 여러 개를 겹치는 것이 그 경계를 어떻게 옮기는지 논하라.
- 문제 16.10 (탐구) 전체 순열, 블록 섞기, 형식 보존 순열이 각각 무엇을 무엇과 맞바꾸는지 앞의 정의 과 앞의 정의 와 앞의 정의 로 적고, 기계 천 대가 같은 데이터셋을 나눠 볼 때 어느 것을 골라야 하는지 논하라.

## 더 읽을 것

- Bandwidth Optimal All-reduce Algorithms for Clusters of Workstations (2009). 링 all-reduce 의 대역폭 최적성 증명과 클러스터 실측. 16.1 절의 하한이 이 논문의 정리다. (16.1절)
- A Digital Signature Based on a Conventional Encryption Function (1987). 머클 트리의 원전. 잎 하나를 뿌리와 경로의 해시로 확인하는 구조가 여기 있다. (16.2절)
- C-Store: A Column-oriented DBMS (2005). 열 지향 데이터베이스. 읽기 부하에서 행 저장보다 한 자릿수 빠른 이유와 열마다 다른 압축. (16.3절)
- Algorithm 235: Random Permutation (1964). 균등 순열의 다섯 줄. 16.4 절의 정리가 이 알고리즘이다. (16.4절)
